# Milestone 5b2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let Varyk code use Varyk packages, to any depth, with every Varyk package compiled by `varyk` from its `.vr` sources, and make `varyk` the only builder of a Varyk package.

**Architecture:** A package's `Cargo.toml` names its `.vr` root as cargo's target, so cargo can read it; `varyk init` writes no `build.rs` or stub and `varyk emit` goes. A new `packages.rs` asks `cargo metadata` for the graph, finds the Varyk packages of the build, and refuses every other way of reaching one. Each such package is checked as a program of its own and its `pub` items are imported into its users' tables; the driver writes one crate per package under `target/varyk/packages/`, rewrites dependency edges to those crates, and cargo builds the program's hidden crate as before.

**Tech Stack:** Rust stable, edition 2024, MSRV 1.85. No new dependencies: `serde_json` and `toml` are already in `varyk`.

**Spec:** `docs/specs/2026-10-02-milestone-5b2-design.md`. "Spec 4.1" refers to its sections, "M3 §n" and the like to the earlier specs. Read it before any task.

- When `varyk` builds a program (`build`, `run`, `test`), a Varyk package's build script and shipped Rust are never compiled or run (spec 3); no such path may hand cargo a source package. `varyk publish`'s `cargo publish` verification is plain cargo and stays as it is.

- Every new program example has an inline expected string in `crates/varyk/tests/examples.rs` (`route` is a library, exercised through `trip`).

## Development Approach

- TDD per task: a failing test first, the minimal code, then the task's gate. Unit tests beside the code; fixtures, snapshots, and integration tests under `crates/varyk/tests/`.
- Each new code lands in the task that first produces it, with its fixture under `tests/fixtures/errors/v<code>_<case>/`, its registration in `tests/errors.rs`, and its `docs/language.md` row (the reference test needs a row for every registered code). Headlines in plain words, Rust words in notes.
- Fixtures whose `Cargo.toml` lists a dependency besides `varyk-std` run from a temporary copy (generalize the existing `package_dir` copier in `tests/common/mod.rs`, no third copier), use only `path` dependencies, and carry no `varyk-std` line, so they need no network. `varyk` runs with the copy as its working directory and a relative entry, and a dependency's files, which come from `cargo metadata` as absolute paths, are shown relative to the working directory when they are under it, so snapshots carry no temporary path.
- The graph is parsed from `cargo metadata`'s JSON into a small owned struct; unit tests feed it recorded JSON files under `tests/fixtures/graph/` (captured once from real cargo, trimmed to the fields read), so they run without cargo.
- Packages are imported through the existing imported-item machinery (M3 §4.1), not a second symbol table: an imported item gains the package it belongs to.
- Package crates are written with the existing `write_files` in `driver/generate.rs`, which already writes only changed files and removes stale ones; no new helper.
- Not needed and why: a cache of the graph (spec 4.1 says add one only if measured); mapping a package's rustc errors to its `.vr` lines (cut, spec 2.6); removing stale package directories (spec 4.3); any change to `varyk add` (it stays a pass-through, now that the manifest has a target).
- Commits: one or more conventional commits per task on the branch; the milestone merges as one `feat!:` like 5b1 (breaking: `varyk emit` removed, `init`'s output changed, V0406 on existing packages).
