# Milestone 5b3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a `.rs` facade declare the four signature shapes a database package needs (a result type chosen from where it goes, any number of scalar values, literal-only text, `varyk_std::Error`), let a `.vr` file re-export an item with `pub use`, and add `varyk add sql`, so `varyk-sql` can be written in Varyk with a thin Rust facade.

**Architecture:** The importer (`interop/`) learns four new `RustTy` shapes and records them on `ImportedSig`; the type checker fills a result type from the expected type the way `json::parse` does, checks literal-only and trailing arguments at the call, and the backend writes a turbofish and a `vec![Value::from(..)]`. `varyk-std` gains `Value`. `pub use` is a `use` with a visibility that the resolver registers as a second name for the item and the backend writes as `pub use crate::..;`. `varyk add` gains a one-row shorthand table.

**Tech Stack:** Rust stable, edition 2024, MSRV 1.85. No new dependencies in `varyk` or `varyk-std`; the test fixture package uses `serde_json`.

**Spec:** `docs/specs/2026-10-03-milestone-5b3-design.md` ("spec 2.1" refers to its sections; "M3 §n" and the like to earlier specs). The package it serves is specified in `Varyk-Lang/varyk-sql`'s `docs/specs/2026-10-03-varyk-sql-design.md`. Read the spec before any task.

## Review Focus

Inputs the spec implies but no listed test exercises, most likely to bite first. Each has a test in the task that owns the code.

1. A trailing value that is a place, not a name: `user.age`, `names[0]`, or a `match` result; it is read, the root stays usable, and the generated `Value::from` reads the place. Task 3.
2. A `usize` from `.len()` as a trailing value is V0218 whose help says `as i64`, not a confusing V0201. Task 3.
3. A string literal with escapes (`"a \"b\" c"`) satisfies a literal-only parameter and is written unchanged. Task 2.
4. A result-typed call passed straight to another call, `show(db.one("..").await?)`, takes `T` from `show`'s parameter type; returned from a function, from its return type. Task 4.
5. `pub use a::item;` where `a::item` is itself a `pub use` of `b::item` resolves to `b`'s item and generates `pub use crate::a::item;`, which Rust accepts. Task 5.

## Development Approach

- TDD per task: a failing test first, the minimal code, then the task's gate. Unit tests beside the code; fixtures, snapshots, and integration tests under `crates/varyk/tests/`.
- Each new code lands in the task that first produces it, with its fixture under `tests/fixtures/errors/v<code>_<case>/` (a `main.vr` plus an `ext.rs` where the case needs a facade, as `v0108_unit_inside_rust_type` has), its `error_case!` registration, and its `docs/language.md` row, since the reference test needs a row for every code in `ALL`.
- New signature shapes are new `RustTy` variants mapped by `Mapper::sig` into fields of `ImportedSig`, not a parallel structure; refused shapes stay `Opaque` with a note added to `uncallable_note`, so V0108 keeps working as today.
- A `varyk_std::` path in a signature is recognised by one helper in `interop/signatures.rs` (`std_item(path) -> Option<StdItem>` for `Error`, `Value`, and the serde bound, with or without the `varyk_std::serde::` prefix for the bound), used by every task that reads one.
- The call site is the only place the new checks run (spec 3): literal-only and trailing arguments in `arguments`, which both free calls and method calls reach.
- Codegen snapshots are `insta` snapshots of `--emit-rust` output on fixtures under `tests/fixtures/codegen/`, as today.
