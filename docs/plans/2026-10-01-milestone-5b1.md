# Milestone 5b1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Varyk `async fn` and `.await`, started calls that give a `Task<T>`, `Task::all` and `Task::all_settled`, `Shared<T>`, and `time::sleep`, on a multi-threaded tokio runtime inside `varyk-std`.

**Architecture:** The pipeline is unchanged. `async` and `.await` are new syntax; the checker marks every call to an async function as awaited or started from what follows it; started calls are owned slots in borrow analysis and a `match` plus `::varyk_std::Task::start(async move { .. })` in the backend. `Task`, `Shared`, and `time::sleep` are rows of the standard table, like 5a's `json` and `Error`. `Shared<T>` is `std::sync::Arc<T>` with no wrapper; `varyk-std` gains `run`, `Task`, and `time`.

**Tech Stack:** Rust stable, edition 2024, MSRV 1.85. `varyk-std` gains tokio (`rt-multi-thread`, `time`; no macros) and futures-util (default features off, `alloc`). No new dependencies in `varyk` or `varyk-syntax`.

**Spec:** `docs/specs/2026-10-01-milestone-5b1-design.md`. "Spec 2.4" refers to its sections, "M5a §n" and the like to the earlier specs. Read it before any task.

## Review Focus

Inputs the spec implies but no example exercises, most likely to bite first. Each has a test in the task that owns the code.

1. A function that starts a task and then returns early through `?` or `return` cancels it: a task that would print after a short sleep never prints. Task 4.
2. `Task::all` over more than 30 `Result` tasks whose last one fails first returns that `Err` at once, and over an empty `Vec` returns an empty `Vec` (or `Ok` of one) without hanging. Task 1 (unit) and task 5 (run).
3. A started call whose argument is itself an awaited call (`let t = f(g().await);`), and one with no arguments (`let t = refresh();`), evaluate in order and compile. Task 4.
4. A single file whose only `varyk-std` use is an async `main` gets the dependency; a package with only an async `main` and no `varyk-std` line is V0404. Task 3.
5. A panic inside a task reaches the waiter through `t.await` and through `Task::all`, and the program exits as a panic in `main` would, without hanging. Task 1 (unit) and task 4 (run).

## Overview

Eight tasks. Task 1 builds the runtime half in `varyk-std` alone. Task 2 renames every live `Task` struct to `Item`, so the name is free. Task 5 adds `Task::all` and `Task::all_settled`. Task 6 adds `Shared<T>`. Task 7 imports `pub async fn` from `.rs` modules and maps rustc's thread errors to V0901. ## Development Approach

- TDD per task: failing test, minimal code, the task's gate. Unit tests beside the code; snapshots and integration tests under `crates/varyk/tests/`.
- Every new call is a `Builtin` row plus a soundness template plus a `docs/language.md` line, following 5a's `time`-like module rows (`json`, `log`: `Owner` plus `path_owner`) and `Error::new` (an associated-function row under a type owner).
- Each new code lands in the task that first produces it, with its fixture under `tests/fixtures/errors/v<code>_<case>/`, its registration in `tests/errors.rs`, and its `docs/language.md` row (the reference test needs a row for every registered code); headlines in plain words (spec 8).
- Started-call arguments reuse the owned-slot machinery (`borrow/slots.rs`) with a new `Slot` variant whose wording carries the "the task may outlive this function" note; no new analysis beyond the place rules of spec 2.3 and 2.4.
- Generated temporaries follow `log_call`'s `match` shape and `varyk_N` names.
- Not needed and why: a `Send` analysis (Varyk types are always `Send + Sync`; rustc's error at a started call becomes V0901, spec 5); a tokio dependency in packages (`run` builds the runtime with tokio's builder); a `Shared` wrapper (`Arc` auto-derefs).
- Soundness cases for async code: task 3 adds an `is_async` marker to a soundness case, and the harness (`function()` ~2013, the `MUST_TEST` wrapper ~2727) then writes `async fn` or `#[test] async fn`; every later async case in `MUST_PASS`, `MUST_REJECT`, and `STRICTER_THAN_RUST` uses it, and async tests get a list of their own beside `MUST_TEST` (a `&[&str]` with a fixed `fn t{index}()` wrapper) whose wrapper writes `#[test] async fn`. The harness already builds against `crates/varyk-std` through `VARYK_STD_PATH`.
